Quick start.

Use the Windows installer from Releases, or run it from source with Node 22 and pnpm.

# from source
git clone https://github.com/mrigankad/Shiftwell
cd Shiftwell
pnpm install
pnpm -r build
node apps/daemon/dist/server.js
# the board opens at http://127.0.0.1:4520

# or use the command line
shiftwell start
shiftwell status
shiftwell run "fix the login bug" --account "Claude A"

Questions.

Does Shiftwell read or store my login tokens?

No. Each account signs in through the vendor's own login inside its own profile folder. Shiftwell reads the status line the CLI emits, the usage endpoint the CLI exposes and the transcripts it writes, and never opens auth files.

Which providers work?

Eight: Claude Code, Codex and Gemini, plus Kimi, Grok, DeepSeek, NVIDIA NIM and Ollama Cloud as API-key accounts that run through the Codex CLI.

Is auto-rotation on by default?

No. It is opt-in. With it on, an active run on an account at its stop line is handed to the account with the most room, at most once per 30 minutes per run.

Does anything leave my machine?

The daemon listens on 127.0.0.1 and the app loads from it. Your work is not sent to a Shiftwell server. The CLIs talk to their own vendors, as they always do.

Check the terms of your plans

Shiftwell runs the official tools, one account per folder, and does not pool or share accounts. Each vendor sets its own terms, so read the ones that apply to your plans.

What is still unproven?

A first end-to-end run with real signed-in accounts is still to do, and the chat-completions shim and Gemini transcript parsing have not yet been tested against live providers.
